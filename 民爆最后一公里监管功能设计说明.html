1.2 一句话结论

先把“人（四大员+测量技术员+安全监管）、库（销售库/使用库）、车、项目、路线”五类主数据建起来（治安管理员可在小程序端直接维护，含维护留痕），再把民爆物品从“库房出库”到“现场起爆/销毁或退库反向回库”的交接节点全部搬进小程序：计划走“测量技术员填报→安全监管签字→项目负责人审核”三级流（当日 24:00 前报次日计划）；出库双人双锁两步签，可一单多点合并出库；押运按载重选车、卸货点序列可调、沿途打卡点逐点扫码；到场按卸货点逐点核量；爆破由安全监理选共核验人并手签；剩余物走销毁或退库（反向押运回原库）。公安按作业量分级介入检查（600kg 以下抽查、600–1200kg 工区警务室到场、1200kg 以上治安大队到场）；每个节点自动记录日志并支持按模板导出文件；节点数据汇聚为统一接口（/bb/overview/*）供自建俯瞰大屏（GIS 一张图）与小程序核验页共用，PC 管理后台承担主数据维护、检查配置与统计分析，形成“计划—出库—运输—到场—爆破—核验”可回放、可检查、可导出的一条链。

2.2 核心矛盾（设计要解决的三对矛盾）

  1. 纸质台账 vs 实时监管：节点必须“发生时即录”，不能事后补录 → 用定位时间戳 + 批次登记强制前移录入时点。
  2. 数据真实性 vs 录入便利性：一线人员不愿填长表单 → 时间/位置/数量尽量系统自动预填，人工（安全员/监理）只做确认与差异说明。
  3. 移动端操作 vs 大屏态势：民警既要远程核验又要看全局 → 同一套数据两个视图（小程序卡片 + 自建俯瞰大屏），核验页内嵌俯瞰，两者同源。

3. 业务链路设计

3.0 主数据建模（底座）

四类主数据构成监管底座，业务节点数据均依赖其关联：

公司(负责人,资质) ──1:N── 人员(四大员/监理/测量技术员/安全监管, 资格证)
      │
      ├─1:N── 库房(销售库/使用库, 坐标, 库管员[]·双人双锁)
      │            └─1:N── 库存(雷管/炸药/导爆索, 品种规格, 存量)
      │
      ├─1:N── 车辆(车牌, 车型, 载重) ──N:1── 驾驶员(资格证)
      │
      ├─1:N── 路线(起运库房→终点作业点, 途经道路, 里程, 沿途打卡点[])   ← V1.3 新增（自录）
      │
      └─1:N── 项目(工区, 关联公司) ──1:N── 作业点 / 作业计划

3.4 公安分级检查的环节与触发

  • 可检查环节：六节点（计划/出库/运输/到场/爆破/核验）任一处均可由民警或责任单位发起公安检查任务（K01）。
  • 分级口径：以“单次作业量（kg）”为阈值依据（雷管按 TNT 当量折算，折算系数后台可配）。
  • 到场要求：系统依据作业量自动判定所需到场级别（抽查 / 工区警务室 / 治安大队），并派发对应单位的到场任务（K05）。
  • 留证：每次检查必须上传照片（K03），检查项配置化（K02），结果可整改闭环（K06）。

7.2 三条关键技术的落地方式

① 到达时间怎么算（需求 4 的核心，Q1 确认：以安全员确认为准）

系统预填（提速，非权威）：
  定位上报流 → 服务端围栏判定（Redis GEO）命中 → suggest_arrive_time（GEOFENCE）
  未命中则取轨迹最近点 collect_time（GPS），写入 suggest_arrive_time
       ↓ 安全员打开「到场接收」(D02)
  展示建议值，安全员确认或修正后落库 arrive_time
       ↓ 权威值
  arrive_time_source = 安全员确认来源（GEOFENCE/GPS/MANUAL）
  无信号时手工填入必填原因，进入审计列表
→ 到达时间以安全员确认为准，系统预填仅作提速，不自动落库为终值

② 三量平衡怎么校验（需求 5 的核心，Q4 确认：允许跨日）

出库量 OUT、实爆用量 USE、退库量 RET、损耗/盲炮 LOSS。 校验 OUT = USE + RET + LOSS；退库可跨日归集到同一出库单（t_bb_return.out_id 关联），不平不允许提交完成；差额 ≤ 最小计量单位 → 提示，否则生成异常单，必须民警确认后才能置“已完成”。

③ 俯瞰大屏与小程序的“一起展示”（需求 6、7 的核心，Q3 V1.4 更新：大屏自建）

同一接口 GET /bb/overview/{planId} 返回 {plan, outbound, transport, track摘要, receive, blasting, verify, exception[]}。

  • 自建大屏：中央 GIS 一张图 + 右侧抽屉按节点渲染卡片（本方实现，消费同一 JSON）；WebSocket 推送实时刷新；
  • 小程序核验页：同一 JSON 渲染精简卡片（时间轴 6 节点 + 位置缩略图），点击“全屏”用 web-view 打开大屏只读页（带短时 token）。

→ 一处数据、两处视图，不会出现“大屏有、手机上没有”的口径冲突。
