## 一、前后端与数据库连路

```
小程序 / PC 后台 / 大屏（浏览器）
   │ ① 加载先 GET /api/health + GET /api/all（拉全量）
   │ ② 业务操作改本地数据 → 防抖 1.5s → POST /api/all
   ▼
server/server.js（原生 Node，8080，兼静态服务）
   ▼
server/db.js ──► server/data/minbao.db
                  ├─ t_store_doc  权威存储（一条记录一行 JSON）
                  └─ t_bb_*       业务表镜像，可直接 SQL 查询
```

浏览器打开 8080 即在线模式（顶栏「● 已连接」）；直接双击本地 html 自动退回离线 localStorage 演示模式。

**首拉保护（关键）**：`__mbReady=false` 时不回推；`GET /api/all` 成功后才置 true。避免新浏览器空种子把库里数据清空。

**表对照（演示 SQLite → 生产 MySQL）**：`t_store_doc`（演示专用）｜`t_bb_plan` / `t_bb_plan_item`｜`t_bb_outbound`｜`t_bb_transport`｜`t_bb_receive`｜`t_bb_blasting`｜`t_bb_return`｜`t_bb_destroy`｜`t_bb_verify`｜`t_bb_check`｜`t_bb_node_log`｜`t_bb_master`（生产拆 9 张）｜`t_bb_inventory`｜`t_bb_settings`。上生产只需替换 `server/db.js` 的 `loadDB/saveDB` 两处为 `mysql2`，路由不动。

**已知边界**：演示库是 SQLite（本机无 MySQL）；`/api/all` 是整包快照，强卡口（Q01/Q03/Q09/Q10）在快照路径不生效，走具体业务接口时才拦截；签名与照片是占位字符串。

## 二、多点位报量与负责人运输安排（2026-11-12）

| 需求 | 落地 |
|---|---|
| 作业点位可多选 | 填报页复选框组，勾选后每点生成独立用量卡；切换项目自动剔除不属于该项目的点位 |
| 每点用量独立、互不合并 | 计划新增 `sitePlans:[{site,items[]}]`；`site`/`items` 保留为首点与合计，下游出库/分级/统计零改动 |
| 负责人汇总所辖点位计划 | 负责人首页「所辖作业点计划汇总」按点位分列条数与 kg，底部合计，只统计所辖项目 |
| 负责人核实即安排车辆与押运员 | 核实页「运输安排（提交前必选）」：选车（车型/核定载重/运输证）+ 选押运员（证书/有效期），载重不足直接拦截；提交后写入 `vehicle/escort/transPlan` 并记日志、推消息 |

实测：Z1 120kg+200 发、Z2 60kg+100 发，合计 180.3kg → 落库 `sitePlans` 2 项 → 监管签字 → 负责人按点核对 → 安排 V1+P5 提交 → 状态「待审核」，多点位明细与运输字段均保留；600kg 车配 2000kg 计划被拦截。

## 四、原型快速体验

- 入口选择角色（九角色）
- 推荐链路：技术员多点位报量 → 安全监管手签 → 负责人汇总核实并安排车辆押运员 → 民警审核 → 库管员双人双锁出库 → 押运员扫码签收/发车/打点 → 安全员到场核量 → 安全监理爆破登记/退库/销毁 → 民警核验
- 「我的」页可一键重置演示数据

## 五、核心设计要点

- **三级计划上报**：技术员填报 → 安全监管手签 → 项目负责人审核（选库房/公安责任区，当日 24:00 前报次日）
- **出库双人双锁**：登记签名不扣库存 → 第二位库管员复核生效扣库存
- **一单多点**：合并多计划出库，累计载重限制车辆选择，卸货点可调序、逐点到达逐点核量
- **沿途打卡点**：运输途中扫码打卡（时间/定位/照片）
- **退库按库房类型分流**：使用库出库、未用完必须原路原库退回（不可销毁）；销售库出库、未用完二选一——现场销毁，或退回中间库（库管员入库）；押运员扫码反向押送
- **治安管理员 8 类基础数据维护**：对接数据可修正留痕 + 车辆路线自录
- **全链路日志**：每节点留痕，可按模板导出
- **分级检查**：<600kg 抽查、600–1200kg 工区警务室到场、>1200kg 治安大队到场（阈值可配）
- **俯瞰大屏**：GIS 一张图（作业点/库房/车辆三图层、状态着色、电子围栏）、实时轨迹、事件墙，与小程序同源
