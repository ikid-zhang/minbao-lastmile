# 林安码 · 民爆"最后一公里"监管 小程序原型

纯前端演示原型（HTML/CSS/JS，无后端、无数据库），依据《民爆最后一公里监管功能设计说明》V1.2 实现 7 类角色全流程页面。演示数据全部在前端内存 + localStorage 中造出与流转，可在「我的 → 重置演示数据」一键还原初始场景。

## 打开方式

双击 `index.html`（或本地静态服务打开）。页面为 390px 手机壳，浅色开放页面 + 电光蓝强调（#074ce0）+ 深色段落（#16191f）风格。

## 角色 → 页面覆盖

| 角色 | 首页 | 核心页面 |
|---|---|---|
| 项目负责人 | 作业计划管理（全部/进行中/已结束） | 上报计划（项目/点位/时间 R9 校验/分品种用量/分级提示 R8）、计划详情（审核状态跟踪/变更/撤回）、沿用上次计划一键带出 |
| 库管员 | 出库与台账（待出库/出库单/退库核销） | 出库登记（≤计划量×105% R3 拦截、批次扣库存、签名）、库存台账（J04 分品种规格、安全线）、日常出入库维护（J05 采购入库/移库/盘点）、退库核销入库（E03） |
| 押运员 | 押运任务（待签收/在途/返程押送） | 扫码签收（C01）、人车选择（C02/J06/J07）、发车打点（C04）、在途轨迹动画（C05/C06 偏离预警）、异常上报（C07，丢失/被盗强制拍照）、反向押送（E03） |
| 安全员 | 到场接收任务 | 到达时间确认（D02 权威值=安全员、GEOFENCE 建议值采纳/手工修正审计）、逐品种核量（D03 差异标红、R4 差异必留证+说明，生成异常单 D04）、拍照留证（D05）、签名（D06） |
| 安全监理 | 爆破与退库（待爆破/待退库） | 爆破情况登记（E01 三态结果/盲炮双通知）、四量对照实时平衡（OUT=USE+RET+LOSS，不平禁提交 R2/E05）、退库登记（E02 行级防超退、跨日归集、T+3 预警） |
| 民警 | 监管待办（待审核/待核验/检查中/超24h督办） | 计划审核（A03/R7，驳回必填原因）、远程核验（F01-F06 五项清单+远程调阅、结论归档 R5）、公安检查（K01-K08：分级派发 R8、检查项模板、无照片禁提交、异常项必填说明）、监管统计（I06 指标+异常看板 G05）、异常处置闭环 |
| 治安管理员 | 治安看板（含管理入口） | 主数据管理（J01 公司档案 / J09 待审核生效·驳回 / J10 完整率）、异常督办（G05 待处置 + F04 超24h未核验 + 已闭环记录）、工区与责任民警（R3 调整路由）、分级阈值与规则（K04 阈值调整 / R7 计划审核开关 / 偏离·停留预警开关） |

共享页面：消息中心（角色订阅消息）、我的（切角色/重置数据/流程说明）。

## 演示全流程（建议按序操作）

1. **民警** → 待审核计划 `BBJH20261103001` → 审核通过
2. **库管员** → 待出库 → 出库登记 → 演示快速签名 → 提交出库（库存扣减）
3. **押运员** → 待签收 → 模拟扫码 → 确认签收（生成运输单）→ 在途 → 发车 → 等待约 12s 轨迹动画跑完，自动进入作业点围栏生成建议到达时间
4. **安全员** → 待接收 → 采纳建议值 → 拍照留证 → 演示快速签名 → 提交接收
5. **安全监理** → 待爆破 → 爆破登记（默认"正常·有返库"，实际用量默认非全耗）→ 提交 → 退库明细 → 提交退库单
6. **押运员** → 返程押送 → 确认接收·发车反向押送 → 等 12s 到库
7. **库管员** → 退库核销 → 确认入库（库存按批次回加）
8. **民警** → 待远程核验 → 五项清单 → 出具核验结论（链路归档，计划"已完成"）
9. 可再走 **分级检查**（K05 自动派发）、**异常差异分支**（安全员核量改小 → 强制差异说明+留证 → 异常单 → 民警"现场核实·处置闭环"后才能爆破 D04）、**押运异常上报**、**发起检查 K01**、**项目负责人新建计划**（<6h 会被 R9 拦截）

## 分支/规则验证点

- R3 出库超计划量×105% 拦截；R4 差异必留证；D04 差异未闭环禁止爆破
- R2 四量不平禁提交；R5 核验 24h 督办；R7 民警审核开关；R8 分级检查阈值（<600 抽查 / 600–1200 工区警务室 / >1200 治安大队）
- R9 提前 6h 填报拦截；R10 作业出库与日常出入库共账
- 行级防超退（退库量不可超剩余量）

## 技术说明

- `js/data.js`：主数据（人员/车辆/库房/项目/点位）+ 种子业务数据 + 状态机流转函数 + localStorage 持久化（库存随单据快照同步，刷新不串数据）
- `js/core.js`：手机壳路由栈、弹层/表单组件、手写签名（含演示快速签名）、轨迹动画（正向/反向）、六节点时间轴
- `js/pages-a/b/c.js`：各角色页面
- `css/app.css`：设计令牌与组件库（ground #fcfcfd / accent #074ce0 / field #16191f；Host Grotesk + Instrument Sans，中文回落 PingFang SC）

## 2026-11-03 增量：工区归属 + 安全员状态分层

**工区（新增主数据 MASTER.workareas）**
- 计划上报表单新增必选「所属工区」（顺序：工区 → 项目 → 作业点；项目列表按工区过滤，项目与工区不匹配会被拦截）
- 计划提交后仅进入该工区责任民警待办（种子：青龙山工区→刘峰 POL2 · 龙泉工区→王卫民 POL1）
- 民警首页新增工区身份条（可切换工区民警，演示用）；待审核/待核验/在管/检查/统计全部按工区过滤；跨工区计划审核与核验页直接拦截
- 消息按工区定向推送（`msg.area`），民警消息页只看本工区
- 卡片、计划详情、审核页均展示所属工区与责任民警

**安全员「运输中 / 待接收」业务分层**
- 运输中 = 车辆在途：只读跟踪卡（进度条、已行驶时长、点击弹出在途跟踪），**不提供接收入口**
- 待接收 = 已进入作业点围栏并生成建议到达时间：出现「去核量接收」任务卡
- 双重防护：接收页对未进场车辆直接渲染拦截页；submitReceive 兜底校验 tr.status==='已到达'

## 2026-11-04 增量：治安管理员界面重构（基础数据 + 预警和看板）

- 工作台重构为两大组：
  - **基础数据（7 项）**：民爆公司 / 民爆点位 / 库房 / 四大员 / 项目备案 / 项目负责人 = **对接展示**（只读，省民爆信息系统每日 06:00 同步，带"对接"标签与同步说明）；车辆 = **自录**（保存即生效）。

## 2026-11-04 增量：治安管理员发起公安检查（K01 全域）

- 工作台「预警和看板」新增入口 **发起公安检查**（admin-check-new）：任一作业点（全域，不限工区）× 六节点任一环节 × 检查项可增删（K02）。
- 两种发起方式：
  1. **派发到场单位执行**（默认）——按分级阈值自动定到场单位，任务状态「待执行」，推送消息给作业点所属工区责任民警，民警在「检查任务」列表执行（须签到+拍照 K05/K03）。
  2. **治安管理员直接检查并出结论**——须上传照片（K03 拦截）、非合格结论须填意见；结论落单即已完成，非合格自动生成异常单进入闭环。
- 监控统计（admin-mon）新增「检查任务（全域）」列表：点单可执行/查看；在途运输卡新增「对该运输发起公安检查」带参直达；任务徽标区分「管理员发起 / 系统按量派发」。
- 配套：`STATUS_CLS` 增加「待执行」徽标；`arriveCheckSign` 兼容「待执行→检查中」；修复直接检查拦截时仍创建检查单的孤儿数据问题（校验前置）。

## 2026-11-04 增量：多库管员出库复核 + 一单多点合并押运

### 1. 库管员出库双人签字（双人双锁）
- 出库改为两步签：**登记库管员签名**（出库单 →「待复核」，不扣库存）→ **第二位库管员复核签名**（生效：扣库存、计划→待运输、推送押运员）。
- 入口「库管员」卡片先选身份：钱有德（登记）/ 吴秀英（复核）；登记与复核须为不同人，同一人复核会被拦截。
- 库管员首页新增「待复核」Tab；出库联单展示登记/复核双签名与时间；全程日志留痕。

### 2. 一单多点合并出库 + 多点押运（用户确认方案：出库时一单多点）
- **出库登记**：一次勾选多个待出库计划合并为一张出库单，按作业点拆分明细；实发 ≤计划×105%（R3），合并累计量不得超库存；页面实时显示勾选合计重量。
- **载重校验**：签收时按累计重量校验车辆（新增小型车 川L·33201 载重 600kg 便于演示拦截），载重不足的车辆不可选。
- **卸货顺序**：默认按路线远近建议排序，押运员可 ↑↓ 调整，调整留痕入日志。
- **逐点押运**：运输单生成卸货点序列（stops）；发车后逐点「到达此卸货点（进入围栏）」→ 该计划转待接收；安全员**仅核本点明细**，单点差异生成异常单不阻塞整趟；全部卸货点完成后整趟「已到达」、出库单「已到达」（中间态「部分到达」）。
- 种子数据新增：PL5（BBJH20261104002，待出库，可与 PL2 审核后合并演示）、保管员 P9 吴秀英、车辆 V3。

### 3. 治安管理员基础数据维护（8 类，含新增路线数据）
- 基础数据从「只读对接展示」升级为**可维护**：民爆公司 / 点位 / 库房 / 四大员 / 项目备案 / 项目负责人（对接类，可本地修正并标记留痕）+ 车辆 / **路线**（自录即生效）。
- 通用维护表单 adminForm(type, id)：按类型字段定义生成表单（下拉选公司/工区/库房/作业点、数字校验、路线打卡点按行录入）；新增/编辑/停用/恢复全留痕于「维护记录」（DB.masterLog，最多 50 条）。
- 路线数据（MASTER.routes）：起运库房、终点作业点、途经道路、里程、沿途打卡点、启用状态；押运员签收页新增「路线快选」，套用后自动填充途经路线与沿途打卡点，仍可手工增删改。
- 停用即隔离：停用后业务节点不可引用；对接类修改标注「源头系统同步不覆盖本地修正」。
