# 民爆"最后一公里"全流程监管平台 · 功能清单

> 版本：2026-11-04 · 依据小程序原型（9 角色）与公安监管业务规则整理

## 一、企业侧功能

| 一级功能 | 二级功能 | 功能描述 |
|---|---|---|
| 身份与入口 | 角色入口 | 9 类角色（项目负责人/库管员/押运员/安全员/安全监理/民警/治安管理员/测量技术员/安全监管）进入各自工作台 |
| 身份与入口 | 库管员身份选择 | 库管员含登记（钱有德）与复核（吴秀英）双身份，登录时选择，双人双锁分离 |
| 身份与入口 | 消息中心 | 计划审核、出库、检查、异常等业务消息按角色推送 |
| 计划上报 | 测量技术员填报 | 按作业点位逐点填报爆破计划（品种/规格/数量），当日 24:00 前提交次日计划（超时拦截） |
| 计划上报 | 安全监管签字 | 各作业点计划须经该点位安全监管审阅并**手写签名**后才推送项目负责人 |
| 计划上报 | 项目负责人审核提交 | 汇总各点计划，审核时必选**出库库房**与**公安责任区**，提交后路由至对应责任民警 |
| 计划上报 | 24 点时限控制 | 次日计划须在当日 24:00 前完成负责人提交，超时拦截并提示 |
| 出库管理 | 一单多点合并出库 | 库管员一次勾选多个待出库计划合并为一张出库单，按作业点拆分明细 |
| 出库管理 | 双人双锁复核 | 登记库管员签名后出库单为「待复核」且**不扣库存**；第二位库管员复核签名后方生效扣库存（同人复核拦截） |
| 出库管理 | 发料校验（R3） | 实发 ≤ 计划 ×105%，超出拦截须民警线上审批；合并累计量不得超库存 |
| 出库管理 | 出库联单与二维码 | 生成 BBCK 联单编号与二维码，双人签名上链展示，推送押运员扫码签收 |
| 押运管理 | 扫码签收 | 押运员扫联单二维码签收，逐品种核对数量，实名绑定押运员 |
| 押运管理 | 人车绑定与载重校验 | 选择驾驶员/车辆（主数据 J06/J07）；按合并累计重量校验，载重不足车辆不可选 |
| 押运管理 | 路线快选 | 从治安大队维护的启用路线中套用，自动填充途经道路与沿途打卡点，可手工调整 |
| 押运管理 | 卸货点顺序调整 | 多作业点默认按路线远近建议排序，押运员可上下调整，调整留痕入日志 |
| 押运管理 | 沿途打卡点设置 | 签收时设置沿途打卡点序列（支持增删），发车后逐点执行 |
| 押运管理 | 发车打点 | 发车记录服务端时间 + 定位双写，开启 30s 间隔轨迹上报（C04/C05） |
| 押运管理 | 途中扫码打卡 | 途中每到一个打卡点须扫码打卡，记录打卡时间、定位、现场照片（缺一不可） |
| 押运管理 | 偏离与异常上报 | 轨迹偏离 >500m×3 点判异（C06）；押运员可主动异常上报（C07） |
| 到场接收 | 围栏判定与建议到达 | 车辆进入作业点电子围栏自动生成建议到达时间（GEOFENCE），无信号可手工修正并标注来源 |
| 到场接收 | 在途只读跟踪 | 车辆在途时安全员仅可查看进度，不可提前核量接收 |
| 到场接收 | 逐点核量接收 | 多点押运按卸货点逐点核量，安全员仅核本点明细（D02–D06） |
| 到场接收 | 差异处置（R4） | 实收与实发不符标红，差异必填说明并拍照留证，自动生成异常单推送民警与库管员，不阻塞整趟 |
| 爆破与核验 | 爆破登记 | 安全监理登记爆破时间、方式、效果、实际消耗（四量归集） |
| 爆破与核验 | 共作业人员核验 | 爆破后安全监理须选择技术人员/安全员等共同核验人（≥1 人） |
| 爆破与核验 | 监理手签 | 安全监理完成核验前须**手写签名**，未签名不可提交 |
| 剩余物处置 | 销毁分支 | 未用完爆炸物可登记销毁，逐品种记录销毁量、销毁原因并拍照留证，生成 BBXH 销毁单 |
| 剩余物处置 | 退库分支 | 生成退库单（BBTK），押运员扫码确认退库量/驾驶员/押运员，按原路线反向押运回原库，库管员核验入库恢复库存 |
| 剩余物处置 | 四量平衡 | 计划量、出库量、使用量、退回/销毁量闭环校验，异常生成提示 |

## 二、公安侧功能

| 一级功能 | 二级功能 | 功能描述 |
|---|---|---|
| 计划审核 | 分级管理（K04） | 按作业量自动分级：抽查 / 工区警务室到场 / 治安大队到场，达到阈值自动生成到场检查任务 |
| 计划审核 | 民警线上审核 | 责任民警按工区接收计划，通过/驳回（驳回须填原因），超 105% 放行审批 |
| 公安检查 | 民警发起检查 | 民警对管辖计划按六节点模板（出库/运输/到场/爆破/退库/核验）发起线上检查 |
| 公安检查 | 管理员发起检查 | 治安管理员可对任一计划任一节点发起检查：派发模式（自动匹配分级单位并推送责任民警）或直查模式 |
| 公安检查 | 检查执行与整改 | 检查项逐项合格/不合格，不合格生成异常单并责令整改，闭环销号 |
| 现场核验 | 六项核验（Q 模块） | 民警到场核验：证照、警戒、在岗、视频、台账等六项逐项确认，生成核验结论 |
| 监督执法 | 在途监控 | 全域在途车辆监控（车辆、路线、进度、轨迹），可对任一在途运输发起公安检查 |
| 监督执法 | 异常督办 | 全域异常单列表，督办处置直至闭环，纳入闭环率考核 |

## 三、治安管理员功能

| 一级功能 | 二级功能 | 功能描述 |
|---|---|---|
| 基础数据维护 | 民爆公司数据 | 对接数据可本地修正维护：公司名称、法定代表人、许可证、资质有效期 |
| 基础数据维护 | 民爆点位数据 | 作业点名称、所属项目、围栏半径的新增/修正/停用 |
| 基础数据维护 | 库房数据 | 销售/使用库房信息维护，库存台账只读展示，停用后业务节点不可引用 |
| 基础数据维护 | 四大员数据 | 爆破员/安全员/保管员/押运员档案维护（岗位、公司、证照、有效期），对接数据本地修正留痕 |
| 基础数据维护 | 项目备案数据 | 项目、所属工区、爆破类型、作业范围、备案有效期维护 |
| 基础数据维护 | 项目负责人数据 | 项目负责人档案维护（随公司建档 J01/J02） |
| 基础数据维护 | 车辆数据（自录） | 车牌、车型、核定载重、年审到期自录维护，车牌格式与载重范围校验，保存即生效 |
| 基础数据维护 | 路线数据（自录） | 押运路线维护：起运库房、终点作业点、途经道路、里程、沿途打卡点（按行录入）、启用状态；押运签收可直接套用 |
| 基础数据维护 | 维护记录留痕 | 全部维护操作（新增/修正/停用/恢复）自动留痕，标注对接数据修改不覆盖源头同步 |
| 基础数据维护 | 主数据审核（J09） | 企业申报的新增主数据待审核列表，审核生效/驳回 |
| 预警和看板 | 治安管理员看板 | 闭环率、核验覆盖率、检查覆盖率、未闭环异常、主数据完整率、资质临期提醒 |
| 预警和看板 | 分级阈值与规则 | 到场检查阈值与规则开关配置（K04） |
| 预警和看板 | 监控统计 | 在途运输、预警记录、异常督办全域监控（G05/K06） |
| 预警和看板 | 工区与责任民警 | 工区与责任民警绑定配置，计划按公安责任区自动路由（R3） |

## 四、平台公共功能

| 一级功能 | 二级功能 | 功能描述 |
|---|---|---|
| 全链日志 | 环节日志记录 | 计划/出库/运输/到场/爆破/退库/核验/检查各环节自动记录操作人、动作、时间（NODE 口径） |
| 全链日志 | 日志查看与导出 | 按计划查看全链日志时间线，按模版一键导出 txt 监管档案文件 |
| 电子围栏 | 围栏与轨迹 | 库房/作业点围栏半径维护，在途轨迹上报、偏离判异、到达判定（C05/C06/C08） |
| 数据安全 | 本地演示与重置 | 演示数据本地存储（localStorage），「我的」页一键重置还原种子场景 |
